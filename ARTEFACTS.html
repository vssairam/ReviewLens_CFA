1. The assignment

A restaurant chain or online store gets 200 to 500 reviews a week from Google, Zomato, Swiggy and Amazon, in English, Tamil and Tanglish (Tamil typed in English letters). A manager reads them by hand, so urgent complaints are missed for days and nobody can say, with numbers, what customers complain about most. The brief asks for a tool that turns the week's reviews into tagged, prioritised insights and a report a manager can act on in five minutes.

  • Upload a CSV with the columns review_id, date, platform, rating, review_text.
  • A LangChain chain per review returns a fixed structure: sentiment, category, urgency, a one-line summary and a polite suggested reply.
  • Mixed language: Tamil and Tanglish reviews are understood and summarised in English.
  • A second chain reads all results and writes top complaints, top praises and 3 action items.
  • A dashboard with the sentiment split, a category chart and a filter for HIGH-urgency reviews.
  • Export the enriched table as a CSV that opens correctly in Excel.
  • Retry: if the model returns an invalid value, retry that review automatically before marking it needs review.

Design decisions and the reason for each

DecisionReason
All counts and percentages are calculated in pandas, never by the AILanguage models are unreliable at arithmetic. This guarantees the report always matches the table.
AI answers are forced into a typed form (Pydantic); invalid ones are retried, then marked needs reviewEvery review gets all six fields with allowed values, and failures are visible instead of silently wrong.
Two models: a fast cheap one per review, a stronger one for the single weekly reportCost and speed where volume is high, quality where it matters most.
The AI provider is chosen in one function (get_llm())The company can change vendor without touching the rest of the program.
The API key comes from a .env file that is git-ignoredThe secret never appears in the source code or the repository.
CSV saved as UTF-8 with BOMExcel then shows Tamil text correctly.
Review text is treated as data, not instructionsA review reading "ignore your rules" must not change the AI's behaviour.

3. What goes in, what comes out

Input: a CSV with the five columns review_id, date, platform, rating, review_text. The sample sample_data/reviews_week40.csv has 240 rows in English, Tamil and Tanglish, including a few deliberately broken rows.

Each review gets six new fields, each limited to an allowed list (a value outside the list is rejected and retried):

FieldAllowed valuesMeaning
sentimentpositive · neutral · negativeThe customer's overall mood.
categoryfood_quality · delivery · price · staff · packaging · appWhich department the feedback concerns.
urgencylow · medium · highHow fast to reply. High = reply today.
languageEnglish · Tamil · Tanglish · OtherTanglish = Tamil words typed in English letters.
summaryone sentence, always in EnglishLets a manager scan Tamil reviews quickly.
suggested_reply1 to 3 polite sentencesReady to post; in the customer's own language by default.

A review the AI could not tag even after retrying gets the special label needs review in every constrained field, so a human knows to read it.

4. A run, step by step

1

Upload

The sidebar takes the reviews CSV, an optional previous week's enriched CSV (for trend arrows) and a "parallel requests" slider (1 to 10, default 5). The Analyse reviews button stays disabled until a file is chosen.

2

Validate

validate_csv() makes the column names forgiving (capitals and stray spaces ignored), stops with a plain message if any of the five required columns is missing, then removes rows with empty text, rows with no review_id, repeated ids (the first is kept) and rows with an unreadable date. It reports how many rows it kept and dropped. The user's original data is never altered (it works on a copy).

3

Classify (the "map" step)

For each review the program sends the platform, the rating, the text and a software-detected writing system to the per-review chain (prompt | model | structured output). Reviews go in groups of 25, several at the same time, and every answer is checked. Invalid or failed answers are asked again (see section 5).

4

Aggregate

compute_stats() counts sentiment, category, urgency and platform with pandas. Reviews marked needs review are left out of the sentiment maths so they cannot distort the percentages.

5

Report (the "reduce" step)

The report chain receives the exact statistics plus one-line summaries of the negative and positive reviews (most urgent first, at most 300 per group) and returns complaint themes, praise themes and exactly 3 action items. Its answer form has no number fields, so it cannot invent counts. See section 6.

6

Show and export

The page keeps the results in st.session_state and shows three tabs: Dashboard, Weekly report and Reviews table. The enriched CSV is written as UTF-8 with a BOM so Excel opens Tamil text correctly. If the report step fails, the tagged table is still returned.

5. Classifying with retries

A run must survive a bad answer, a network error or a rate limit without losing the other 200+ reviews. analyze_reviews() works in rounds: round 0 is the first attempt, and rounds 1 and 2 re-ask only the reviews that have not yet produced a valid answer.

What counts as valid. The answer must be a proper filled-in form, every constrained field must hold an allowed word, and the summary and the reply must not be blank.

6. Map, then reduce: where the numbers come from

A week of reviews does not fit into one prompt, and a model must not be trusted to count. So the work is split: map (one small call per review) and reduce (one call that reads short summaries). Counting is done in pandas between the two.

A deliberate simplification. The count printed beside a theme is the number of negative (or positive) reviews in that theme's category, not the number of reviews that match the theme's exact wording. This keeps every number exact, but it is coarser than a per-theme count.

7. Tamil and Tanglish

Reviews come in three kinds: English, Tamil script and Tanglish (Tamil words typed in English letters, such as "Delivery romba late, food thanda aagi pochu"). The model understands all three and writes the summary in English. A live run exposed one weakness: the model sometimes labelled Tanglish as "Tamil", so those reviews received replies in Tamil script. The fix is to let the program decide the one thing it can know for certain: which letters the review uses.

Replies follow the customer's language by default (English → English, Tamil → Tamil, Tanglish → Tanglish); the summary always stays in English. Setting REVIEWLENS_REPLY_LANGUAGE=english switches that off.

8. Stretch goals

8.1 Week-over-week trend arrows

After every analysis the week's numbers are saved to history/week_ending_<last date>.json. The next run compares with the most recent saved week that ended before the current week began (a week that overlaps, for example the same file analysed twice, is never used). Alternatively the user uploads last week's enriched CSV in the sidebar. It is pure arithmetic with no AI.

8.2 Replies in the customer's own language

Described in section 7: the prompt carries a reply-language rule, and a setting can switch it back to English.

8.3 The Monday e-mail

send_weekly_report.py runs the whole job with no web page: it takes the newest CSV in inbox/ (or the one given with --csv), validates it, runs the analysis, builds an e-mail with the report in the body and two attachments (weekly_report.txt and reviews_enriched.csv), then sends it. Windows Task Scheduler starts it every Monday at 09:00.

9. The Streamlit app

  • Sidebar: upload the reviews CSV, optionally last week's enriched CSV, choose the number of parallel requests, then press Analyse reviews.
  • Friendly errors: an unreadable file, a missing column or a missing API key stops the run with a plain message, not a crash.
  • Progress bar: advances as each group of 25 reviews is classified.
  • Dashboard tab: four numbers (reviews shown, high urgency, negative share, needs review), a sentiment donut chart, a reviews-by-category bar chart and the table with the suggested replies. The toggle Show only HIGH urgency reviews filters the table and the charts.
  • Weekly report tab: the report text with a Download report (.txt) button.
  • Reviews table tab: the full tagged table with Download enriched CSV (Excel-ready).
  • Memory between clicks: Streamlit re-runs the script on every click, so the results are kept in st.session_state.

12. Tests, results and limits

Automated tests: 12, all passing

The tests use a stub chain, so they need no API key, no network and cost nothing. They check, among other things:

  • validation drops empty and duplicate rows, and a missing column gives a clear error;
  • an invalid answer is retried and a review that keeps failing becomes needs review;
  • report numbers come from pandas, and the CSV export carries the BOM;
  • the reply-language rule, trend numbers and arrows, and that history picks only an earlier week;
  • the language label is corrected by script, and the e-mail is built and sent with TLS login (with a clear error when settings are missing).

Running python -m pytest -q while preparing this guide gave 12 passed.

What the live runs showed

These results are recorded in docs/ReviewLens_Artefacts.md (23 November 2026) from live runs against OpenAI; they were not re-run for this page.

A defect the live run found, and the fix. The model sometimes labelled Tanglish reviews as "Tamil", so they received Tamil-script replies. The program now detects the writing system itself, gives it to the AI as a hint and overrules a wrong "Tamil" label (section 7). One Tanglish praise review still received an English reply, which is a model choice and harmless.

Known limits

  • The count beside a report theme is the number of negative (or positive) reviews in the theme's category, not the number matching the theme's wording.
  • Even at temperature 0 the AI is not perfectly repeatable: two runs of the same file differed by a few HIGH-urgency tags (for example 17 versus 18).
  • Trend arrows need an earlier week: analyse it first (it is saved in history/) or upload its enriched CSV.
  • A person should skim the first run's Tamil and Tanglish summaries; quality depends on the model and the prompt.
  • Reviews are sent to an external AI provider. Do not upload data you are not allowed to share with that provider.
  • The default model names can be changed in .env if an account uses different models.

14. How to run it

python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env          # then put your OPENAI_API_KEY in .env
streamlit run app.py            # upload sample_data\reviews_week40.csv
python -m pytest -q             # optional: the automatic tests

To try the trend arrows, analyse sample_data/reviews_week39.csv first and then reviews_week40.csv.

The Monday e-mail can be rehearsed without sending anything:

python send_weekly_report.py --dry-run     # saves the e-mail to outbox/
python send_weekly_report.py               # really sends (fill the SMTP_* and REPORT_TO lines in .env)
To use Claude instead of OpenAI, set REVIEWLENS_PROVIDER=anthropic and ANTHROPIC_API_KEY in .env. Nothing else changes.
